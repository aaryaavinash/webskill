# 04 — Visual and functional quality gate

A passing build only proves files compiled. A cinematic page needs a rendered review. Use the available browser or screenshot tooling; if unavailable, report that limitation clearly and inspect generated images/video by another means. Do not claim visual quality from source code alone.

## Capture matrix

Capture desktop around 1440×900 at top, 20%, 40%, 60%, 80%, and CTA/end. Capture phone around 390×844 at hero, one middle station, and CTA. Include a reduced-motion capture. Wait for the loader and transitions to settle, but also observe the loader itself and one mid-transition frame. Compare frames side by side to spot repetition and empty sections.

## Judge each frame

1. **Composition:** one clear focal point, readable title, intentional negative space. The object and copy do not overlap at common viewport sizes.
2. **Materials/light:** visible depth, contact/shadow, motivated highlight, readable dark surfaces; no blown whites, muddy AO, or plastic default material.
3. **Typography:** deliberate display/body pairing, fluid sizes, line breaks, contrast, no orphaned words or labels too small to read.
4. **Narrative:** station differs from its neighbors in camera/object/light/copy, while still feeling part of one world.
5. **Interaction:** hint visible within seconds, target looks actionable, input yields an unmistakable visual response and resets.
6. **Page completeness:** real nav, substantive sections, honest CTA destination, footer, mobile layout.
7. **Technical:** no uncaught console errors, broken image/model paths, excessive layout shift, horizontal overflow, loader trap, or unusable frame rate.

## Functional checks

- Navigate with Tab/Enter/Space; labels and focus rings visible. Test Escape/reset if relevant.
- Test touch equivalent and coarse pointer; no hover-only essential action.
- Test reduced motion, WebGL failure/poster fallback, slow load, and failed critical asset.
- Scroll down/up quickly; refresh at a middle section; use a direct anchor and browser back.
- Resize desktop to narrow tablet/phone; ensure camera and typography recompose.
- Confirm no code-facing debug UI or technical explanation leaks into consumer copy.
- Measure actual page/asset weight and frame rate where tools permit. Set a budget based on target hardware; 60 fps on a powerful desktop does not guarantee acceptable laptops.

## Fix order

Fix blocking behavior and broken assets first. Then correct the largest composition issue in the contact sheet. Then lighting/materials, hierarchy/copy, interaction clarity, motion polish, and minor decoration. Re-capture the changed frames after each material fix. Stop optional tweaking once the agreed quality gate passes.

## Delivery report

State what was built, where, what was inspected, and any remaining limitation. If you could not run a visual browser review, say exactly that; do not substitute “build passes” for it.
